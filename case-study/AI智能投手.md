# 案例：AI 智能投手 —— 把生产策略引擎做成可信任的 Agent 产品

> 脱敏个人案例。文中数据均为演示值，生产细节以抽象框架替代。

## 1. 问题

电商商家在巨量千川的广告投放高度依赖人工：一名优化师盯几十上百条计划，夜间无人值守、止损靠手速、错过整点窗口就是真金白银的损失。团队已有一个每小时跑批的策略引擎在生产环境执行判定，但它是"后台脚本"——商家看不见、不理解、不敢授权，价值无法定价。

**真正要解决的产品问题不是"算法准不准"，而是"客户凭什么相信并持续付高价"。**

## 2. 洞察

进场后我确立了三个约束，所有设计从这里推导：

1. **钱证不了。** 增收/省钱是反事实——大促、货品、行情都在变，任何"帮你赚了 ¥X"都会被一句"怎么证明是你不是大促"戳穿，而戳穿一处，整页信任全塌。
2. **不能得罪优化师。** 日常使用者是优化师；"替代人"的叙事会招致一线抵制，产品推不动。
3. **授权是渐进的。** 没人会第一天就把删素材的权力交给 AI。信任必须有可拾级而上的台阶。

## 3. 关键决策

### 3.1 价值证明：从"归因"转向"可核验事实"

页面默认不证明"提升是我们带来的"，只证明四类可核验事实：**托管覆盖**（接管了多少计划与消耗）、**实际动作**（每次执行的前后状态）、**风险兜底**（夜间干预、持续亏损已暂停）、**动作稳定性**（误杀率、撤回率、守线比例）。每一条都能下钻到动作账本逐条核验。"提升对比"只在受控留样条件成立时出现，定位为签约期一次性背书，不做常驻承诺。

### 3.2 授权模型：L1/L2 按账户 + 能力逐项开关

- **L1** = 建议后执行（拍板才动）；**L2** = 授权范围内直接执行，可核验、可撤回。
- 能力逐项授权：不可逆动作（删除素材）默认保留人工拍板；夜间紧急止损独立开关。
- 拍板三出口：**采纳 / 调整后执行 / 这次不动**。"调整后执行"允许用户改建议值，系统记录"你的值 vs 我的建议"——这是最有价值的反馈信号，也是后续"放权引导"的依据。

### 3.3 推荐机制：批次时效

每小时整点巡检出一批建议，**本批未处理自动失效**，不提供历史批次回看。推荐是有时效的请示，不是永远堆积的待办——这既符合投放数据的时效本质，也把"AI 在实时值守"的感受做进了机制里。

### 3.4 动作语言：真实对象 + 锁定词表

废弃早期版本的"四大决策类型"抽象分桶，改为用户熟悉的真实对象与动作：计划 = 暂停 / 调目标投产比 / 改预算；素材 = 追投 / 删除；外加"维持现状"单独计数——**克制本身是卖点**。已发生动作只标三态：`我自动` / `采纳` / `调整后采纳`；"未采纳"不进动作记录，只进建议统计与档案复盘层，保证执行日志里每一条都是真实发生的事。

### 3.5 策略产品化：把引擎判定翻译成第一人称叙事

我逐条读通策略引擎的判定链，把它翻译成前台的"我发现（数据论证）→ 我建议（含为何不更激进）→ 你拍板"结构，并逐卡核对 Demo 呈现与引擎逻辑的一致性。过程中发现一张示意决策卡的动作方向与引擎口径相反（"逼近盈亏线"配了放量方向的调整），推动修正——**产品对外可信度取决于每一句"我建议"都经得起引擎口径的核对。**

## 5. 验证方式

- **机制层**：Demo 内每张决策卡与策略引擎判定口径逐一核对；动作方向、幅度、组合合法性均以引擎为准修正。
- **信任层**：以"文案纪律"清单做静态审查——禁止一切反事实金额表述、人头折算、聚合层术语；聚合层统一业务语言（"持续亏损"），术语只进细节弹窗。
- **鲁棒性**：以"行情差的一周"做压力场景推演——覆盖、动作、兜底、稳定性四类口径在数据难看时依然成立，页面不靠"比上月"做头条。
- **上线效果**：生产运行数据不在公开范围；公开层面以上述可核验机制与验证标准替代效果宣称。

## 6. 反思

- **最值钱的一步是"读透引擎再做前台"。** 不读代码的 PM 只能把策略做成黑盒开关；读透判定链之后，每张决策卡的理由、幅度、边界都有出处，Demo 才经得起投手追问。
- **删功能比加功能难也更重要。** 砍掉 L3 全托管档、砍掉四大决策类型、砍掉常驻对照组，每一刀都是在收窄承诺半径、加固信任。
- **原型债要诚实记账。** iframe 拼装、作用域未联动数据、深链缺失等都写进设计文档的"原型债"清单——原型的职责是定稿交互与口径，不是伪装成工程。
