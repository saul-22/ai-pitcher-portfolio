# 策略产品化框架（抽象版）

> 本文只讲产品层框架：策略引擎如何分层判定、如何被翻译成用户可信的前台呈现。生产规则的完整条件、精确阈值与代码实现不在公开范围。

## 判定链（每小时一轮）

```
拉取分时数据 → 计算指标（历史分位数基准 + 短窗趋势斜率 + 成交密度 + 多窗口累计）
  → ① 前置检查（命中即停：无流量 / 当日调整达上限 / 近 1 小时已调过 → 转观察）
  → ② 计划级匹配（冷启动 / 止损 / 收缩 / 扩量 四族规则，按优先级顺序）
  → ③ 素材级匹配（删除族 / 追投族，新素材保护期内跳过）
  → ④ 未命中规则 → AI 多维评分兜底（高分放量 / 低分收紧 / 中间观察）
  → ⑤ 双层仲裁（计划动作 + 素材动作合成最终动作）
  → L1/L2 闸门 → 直接执行 或 进收件箱等拍板
```

## 产品视角的关键设计

### 1. 指标基准相对化
不用绝对阈值判断好坏，用**该店铺自身历史分位数**作基准（数据不足时逐级降级到全局基准与兜底默认值）。同一条规则在大店小店都成立，冷启动也不会误判。

### 2. 优先级 = 匹配顺序
止损永远先于收缩，收缩先于扩量；扩量按成本水位分档，成本越低动作越激进。**顺序错了动作就错**——这是规则引擎类产品最隐蔽的正确性来源。

### 3. 方向语义必须产品化
降目标投产比 = 放量（放宽回报要求抢流量）；升目标投产比 = 收紧止损。前台每一张决策卡的动作方向都要与引擎口径核对——本项目曾发现一张示意卡把"逼近盈亏线"配了放量方向，逐层修正。

### 4. 三重防抖（克制机制）
- 当日调整次数达上限 → 转观察（止损暂停除外）
- 近 1 小时已调过或用户刚改过目标 → 转观察
- 近 N 小时已命中同类型策略 → 转观察

防抖是把"AI 会不会乱调"的担心做成机制答案。前台把"巡检后判断无需动作"单独计数展示。

### 5. 冷启动保护
新计划按折扣系数放宽盈亏线再判定，避免被误判亏损而止损——**保护探索期**是自动化投放产品最容易忽略的边界。新素材同样有保护期，期内不参与删除判定。

### 6. 删除的多重验证
素材删除一律要求多重条件同时成立（消耗 + 时长 + 无转化 / 亏损 + 质量差 / 密度差 + 亏损），并且默认保留人工拍板。不可逆动作的判定标准必须显著高于可逆动作。

### 7. 双层仲裁的保护逻辑
一条计划可以同时"调投产比 + 删差素材 + 追好素材"（计划级管整体，素材级管增删）。关键保护：**计划要暂停但旗下有值得追投的素材时，计划转为观察**——不因整体止损误杀有潜力的局部。

### 8. 动作值有下限约束
调整后的目标值与原值必须有最小差异；预算变动低于最小步长时按最小步长执行。杜绝"看起来动了、实际没意义"的无效微调。

## 从引擎到前台的翻译

| 引擎层 | 前台层 |
|---|---|
| 规则代号与判定条件 | "我发现"：当时的数据论证（人话） |
| 动作类型 + 动作值 | "我建议"：动作 + 幅度 + 为何不更激进 |
| 优先级 | 收件箱排卡顺序（风险 × 消耗） |
| 防抖转观察 | "维持现状"计数（克制的可见化） |
| 执行结果回写 | 执行日志前后对照 + 档案后效复盘 |

**PM 在这里的职责：读透判定链，保证前台每一句"我建议"都经得起引擎口径的核对。**
