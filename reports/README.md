# 报告系统设计

> 两条平行报告线 + 一套 LLM 渲染契约。演示页：[老板报告卡片 Demo](demo.html)（含 3 场景切换，均为合成数据）。

## 双线设计：同一数据，两种受众

| 维度 | 老板报告 | 优化师执行报告 |
|---|---|---|
| 受众 | 不懂投放的老板 | 专业优化师 |
| 密度 | 低（强信心、每屏少量数字） | 高（计划级明细） |
| 节奏 | 日 / 周一 / 月度 | 每 1/3/6 小时 |
| 载体 | IM 富文本：文字 + PNG 卡片 + 文字 | IM 原生 Markdown |
| 语气 | 叙事化、正向优先 | **纯事实陈述，不教专业者做事** |

**报告长度 = 信号**：短 = 一切正常；长 = 有事值得关注。

## 老板报告：LLM 驱动内容，不驱动布局

卡片布局永远固定（品牌栏 + 核心指标 + 账户诊断 + 状态卡 + 动态 + 关注），老板每周看到同样结构；内容由 LLM 每次生成。

**数据情绪（data_mood）** 由后端按投产比变化率规则判定，决定状态卡变体与叙事基调：

| mood | 基调 |
|---|---|
| strong_growth | 自信、肯定（不用感叹号） |
| steady_growth | 稳健平实——稳本身是成绩 |
| needs_attention | 先说正向，调整一笔带过，重在措施 |
| first_report | 不强调环比，不加欢迎语 |

**渲染链**：数据聚合 → 指令决策（mood/主题/账户展示模式）→ 数字预格式化（LLM 原样引用不做算术）→ 并行〔规则引擎兜底版（永远成功）+ LLM 调用（可失败重试）〕→ 合并 → HTML → PNG → IM 推送。**LLM 挂了报告也能发**——兜底版是可靠性设计，不是备胎。

**LLM 输出六字段各司其职**（身份行 / 每户一句诊断 / 事件叙事 / 格局总结 / 值得关注 / 总结），字段间禁止内容重叠，长度逐字段约束。

## 优化师执行报告：五个反直觉决策

1. **纯事实陈述**。不猜原因、不教优化师做事、不解释 AI 意图、不下情绪判定——专业受众自己判断。
2. **信息密度不均匀**。80% 是日常调投产比，一句带过；止损、加预算等特殊动作 1–2 行说清判断依据。段落顺序按业务量级，首屏即主战场。
3. **置顶"N 条需复核"**。按简单规则筛（当日调整达上限、高消耗零转化），不做"智能判异常"——规则可解释，信任才成立。
4. **元信息后端硬渲染**。时间戳、店铺元数据、需复核清单、@ 人行 LLM 一律不碰；LLM 只写动作段叙事。
5. **一条主报告 + 每人独立 @ 通知**。每位优化师账户范围不同，@ 不能合并。

## 归因口径（与产品一致）

报告只认可核验事实：夜间值守时段的止损与放量动作如实陈述；白天动作只描述"发生了什么"；**不把整体经营算成产品功劳**。数字全部后端预格式化，LLM 禁止算术。
