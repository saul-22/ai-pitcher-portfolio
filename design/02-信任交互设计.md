# 信任交互设计

> 自动化产品的信任不靠宣传话术，靠交互标准件。以下是本产品沉淀的五个关键件。

## 1. 数据抽屉标准件（全产品一套引擎）

「智能优化 · 查看数据调整」与「计划明细 · 档案」共用同一 880px 右抽屉：

- **左数据**：时间粒度（按天/按小时）+ 双轴走势图（消耗柱 + 投产比线 + 盈亏线）+ 明细表
- **右轨（300px）**：档案时间线 +（仅智能优化）可调字段 + 「交给我执行」

**铁律：不另造第二种数据弹窗。** 用户在两个场景看到的是同一套数据语言，学习成本减半，信任感翻倍。

## 2. 档案时间线组件

每条计划一本跨天决策史。每条记录 = 轨道点 + 正文（时间 mono 小字进正文首行）：

- **标题 + 三态标签**（我自动 / 采纳 / 调整后采纳；档案复盘层额外可见"未采纳"）
- **为什么**（why）：当时的数据论证
- **后效复盘**（after）：✓ 有效 / ✗ 未能止住下滑 / ◷ 观察中

**允许认错与认输**是这个组件的灵魂：Agent 复盘自己动作的后效，包括"你的判断对"（用户未采纳且用户是对的）。审计诚实换长期授权。

## 3. 决策卡（请示的标准形态）

```
[严重度点] 计划全称 + ID 副行
我发现：连续 2 天逼近盈亏线（数据论证：实际投产比走势 + 盈亏线）
我建议：目标投产比 3.4 → 3.8，预算下调（并解释为何不更激进）
[采纳，交给我执行]  [这次先不动]        查看数据·调整 →
```

- 主按钮文案统一「采纳，交给我执行」；**不可逆动作保留动词**（「采纳，立即暂停」「采纳，删除素材」）。
- "我建议"必须含**为何不更激进**——展示克制比展示能力更能换来授权。
- 素材卡必须标所属计划。

## 4. 脏状态提交条

开关/抽屉/弹窗即时生效（各自反馈）；**仅自由输入（盈亏线）用脏状态提交条**——默认隐藏，有改动浮出并精确报数（"你改了 N 条…"），保存 / 还原（还原 = 回填原值，非刷新）。高风险数值修改必须有一次显式确认，且用户永远知道自己改了什么。

## 5. 放权引导卡

基于用户**自己的采纳历史**建议升级授权："你近 30 天对止损建议采纳率 92%，可以考虑把止损升为自动执行"。数据来自用户自己的行为，不是产品的自夸——这是 L1 → L2 的信任台阶。

## 文案原则

- Agent 全程第一人称（"我发现 / 我建议 / 交给我执行"）。
- 聚合层用业务语言（「持续亏损」），术语（"跌破盈亏线"）只进弹窗与规则细节。
- 允许认错（"未能止住下滑"）与认输（"你的判断对"）。
- 空状态文案随上下文动态变化，不用死文案。
