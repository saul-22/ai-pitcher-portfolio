# 决策与动作模型

> Agent 如何决策、如何请示、如何被审计——全产品唯一词表。

## 推荐机制：批次时效

- 每小时整点批量巡检全部计划出一批建议；**本批未处理自动失效**，不提供历史批次回看。推荐是有时效的请示，不是堆积的待办。
- 直播间计划优先于商品计划。
- 洪峰口径：本批共 N 条，按风险 × 消耗挑出 M 条成决策卡，其余按动作类型归入低优先级列表（筛选 + 批量采纳）。

## 授权模型：L1 / L2 按账户

| 等级 | 含义 | 审计方式 |
|---|---|---|
| L1 | 建议后执行——你拍板我才动 | 计入建议数与采纳率 |
| L2 | 授权范围内直接执行 | 全部进执行日志，可核验、可撤回 |

- 能力逐项授权：素材追投与删除分开授权；**删除素材默认需拍板**（不可逆动作保留人工闸门）。
- 夜间紧急止损独立开关。
- 放权引导：基于用户自己的采纳历史（"你近 30 天对止损建议的采纳率很高"）建议升 L2，而不是靠宣传话术。

## 拍板三出口

1. **采纳** —— 按原建议执行
2. **调整后执行** —— 可修改建议值，Agent 实时点评你的值；系统记录"你的值 vs 我的建议"，是最有价值的反馈信号
3. **这次不动** —— Agent 记下，可"再次提示"

## 动作词表（锁定）

| 对象 | 动作 | 标签色 |
|---|---|---|
| 计划 | 暂停 | 红 |
| 计划 | 调目标投产比 | 蓝 |
| 计划 | 改预算 | 橙 |
| 素材 | 追投 | 绿 |
| 素材 | 删除 | 紫 |
| 计划/素材 | 维持现状（巡检后判断不动，单独计数） | 灰 |

方向语义（容易搞反，产品必须讲对）：**降目标投产比 = 放量**（降低回报要求、放宽流量）；**升目标投产比 = 收紧止损**。逼近盈亏线时的正确组合是"升目标投产比 + 降预算"，而不是反向。

## 动作记录三态标签

已发生的动作只标三种：

| 标签 | 含义 | 视觉 |
|---|---|---|
| 我自动 | L2 授权内执行 | 灰 |
| 采纳 | 按原建议确认执行 | 蓝 |
| 调整后采纳 | 同方向、偏离超过建议步长 30% | 橙 |

判定口径以**建议步长**为基准：同方向偏离 ≤30% 算采纳；>30% 算调整后采纳；**反向调整、换动作、不动 = 未采纳**。无值动作（暂停/删除/追投）只有采纳与未采纳。

**未采纳不进动作记录**——没有动作发生，执行日志与实时流里不出现；它只进建议统计（采纳率 =（采纳 + 调整后采纳）/ 总建议）与计划档案的复盘层（档案是决策史，可以记"你判断不动"并复盘对错，允许 Agent 认输："你的判断对"）。

## 为什么这样设计

- **三态标签让审计诚实**：日志里每一条都是真实发生的动作，且每条都能回答"谁决定的"。
- **调整后采纳单列**：既承认用户判断的价值，又为策略校准提供带方向、带幅度的反馈数据。
- **维持现状单独计数**：克制是自动化产品最稀缺的信任来源——"盯了但判断不动"必须可见。
