# 投放成果页 · PRD

> 页面结构 / 数据口径 / 文案纪律。

## 0. 这页是什么

投放成果页 = Agent 的托管成果页，登录默认首页。它回答客户第一眼的问题：

> 我为什么要继续为这个 AI 投手付费，甚至扩大托管？

默认展示两类内容：**当前经营表现**（GMV、消耗、投产比、盈利消耗占比——展示但不强归因）与**托管价值**（覆盖、动作、兜底、稳定性——可核验事实，本页地基）。

## 1. 核心机制

```
客户设定：盈亏投产比（保本底线，计划级）
        ↓
Agent 执行：动态调整目标投产比、预算、计划/素材状态
        ↓
目标：让实际支付投产比尽量跑在盈亏线之上，同时把可承接的消耗顶上去
```

- **支付投产比** = 实际结果；**盈亏投产比** = 保本线；**目标投产比** = Agent 操作的出价旋钮。
- 消耗不是天然成本项：对冲量客户，价值是在不破盈亏线的前提下承接更多有效消耗，不是"省消耗"。

## 2. 页面结构（六区块）

### 区块 1 · 当前经营表现
GMV / 消耗 / 支付投产比 / 盈利消耗占比 + 趋势图（近 3/7/15 天联动）。标注"按你设置的盈亏线计算"；可下钻未达线计划。**不 claim 是 Agent 带来的。**

### 区块 1.5 · 试用期对比 + 转化位（条件展示）
仅试用期展示，满期自动收起：接入前后各 N 天日均对比 + 口径脚注。模块底部即转化位：`试用还剩 N 天 · 到期后我会停止值守 →〔继续让我值守〕`——诚实损失提示，不用促销话术。这是付费动线在产品内的唯一落点。

### 区块 2 · 托管覆盖
托管计划数 / 素材数 / 托管消耗占比 / 重点计划覆盖率 + 未托管高消耗计划入口。客户只托管低消耗差计划时，如实提示"主要消耗尚未进入托管"——这是推动扩托管的核心板块，也是数据难看时的诚实出口。

### 区块 3 · 实际动作
按真实对象与动作词表展示（暂停 / 调投产比 / 改预算 / 追投 / 删除 / 维持现状），下钻动作账本：对象、时间、动作前状态、动作内容、执行方式（L2 自动 / L1 采纳）、动作后观察状态。

### 区块 4 · 风险兜底
夜间干预次数、持续亏损已暂停计划数、高消耗异常处理、平均响应时长、连续值守天数。只说"当时已跌破你设置的盈亏线，已暂停处理"，不说"帮你省了 ¥X"。

### 区块 5 · 动作稳定性
误杀率、人工撤回率、追投后守线比例、动作后 24h/48h 观察结果。解决"AI 会不会乱调"的核心疑虑。

### 区块 6 · 提升验证（条件成立才出现）
仅当试用期事前设计了留样组、分组规则提前约定、样本充分时展示托管组 vs 留样组对比。不满足条件时整块隐藏——不显示"暂无数据"，不用事后匹配硬凑对照。

## 3. 关键口径

- **盈利消耗占比** = Σ(盈亏达成计划的消耗) / Σ(总消耗)。每条计划用自己的盈亏线判定，聚合按消耗加权。
- **托管消耗占比** = 托管对象关联消耗 / 总消耗。证明覆盖，不等同于"贡献占比"。
- 时间档 3/7/15 天全页数字联动；自定义区间限制单次跨度并可回看有限天数，超限就地报错。
- L1/L2 严格区分：L1 采纳的执行时机归优化师，不混进"自动执行次数"。

## 4. 冷启动

新客户第一天不空白：绑定后先诊断（可托管计划/素材、可覆盖消耗），数据不足时标"积累中"，回溯模拟必须标注"基于历史数据模拟"。

## 5. 文案纪律

禁止：帮你赚/省 ¥X ｜ 提升归因 ｜ 人头折算 ｜ 省消耗/降本 ｜ 把动作包装成聚合价值桶 ｜ 聚合层用"跌破盈亏线"术语（一律说「持续亏损（已暂停）」）。

推荐：当前经营表现 ｜ 托管消耗覆盖 ｜ 已执行动作（词表锁定）｜ 夜间值守 ｜ 持续亏损已暂停（可逐条核验）｜ 动作账本可追溯。
